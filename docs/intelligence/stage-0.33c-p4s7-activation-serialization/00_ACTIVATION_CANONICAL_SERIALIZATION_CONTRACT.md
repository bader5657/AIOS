## One canonical serializer

The sole governed model is Python JSON serialization with these exact settings,
followed by strict UTF-8 encoding:

```python
semantic_bytes = json.dumps(
    activation,
    ensure_ascii=False,
    sort_keys=True,
    separators=(",", ":"),
    allow_nan=False,
).encode("utf-8")
transport_bytes = semantic_bytes + b"\n"
```

This is a specification, not an activation-creation command or record. No
timestamp or activation JSON instance is generated by this task.

Semantic bytes are exactly the canonical JSON bytes with **no terminal LF**.
They contain no BOM, leading whitespace, or trailing whitespace. Transport
bytes are those semantic bytes plus **exactly one ASCII LF (`0x0A`)**. The file
stored on disk must contain exactly these transport bytes: no second LF, no
trailing spaces, and no CRLF.

The single terminal LF is a governed **transport framing rule**. It is not part
of the JSON semantic object. All semantic re-canonicalization comparisons
exclude that single LF. Implementations must not use whitespace stripping,
newline normalization, or other repairs to make invalid transport acceptable.

## Mandatory future byte-equality enforcement

The separate executor amendment must, before any claim:

1. Read activation transport bytes using the preserved safe file checks.
2. Require exactly one terminal ASCII LF. Reject absent LF, a second LF, CRLF,
   and any other invalid framing; do not normalize bytes.
3. Separate `semantic_bytes = transport_bytes[:-1]`.
4. Parse semantic JSON as strict UTF-8 with duplicate-member rejection.
5. Validate the closed schema, exact value types, timestamp lexical and calendar
   validity, and all governed bindings.
6. Canonicalize the parsed object with the sole serializer defined above.
7. Require `canonical_bytes == semantic_bytes` exactly.

Any metadata, framing, decoding, parsing, schema, value, serialization, or byte
comparison failure must produce `PRECONDITION_FAILED` before claim. No claim,
staging, or publication may occur on these failures. Exception paths must also
fail closed before claim; parser success alone is insufficient.

`PRECONDITION_FAILED` and zero claim, staging, and publication calls:

- Reordered keys.
- Extra spaces between JSON tokens.
- Indentation or pretty printing.
- CRLF framing.
- Missing terminal LF.
- Two terminal LFs.
- Trailing space before LF.

- Wrong `pr_number` JSON type, including boolean, float, exponent notation,
  and string; a wrong integer value must also fail before claim.

A positive case must establish that the exact governed canonical semantic bytes
plus exactly one LF pass serialization validation when all other prerequisites
are satisfied. Tests must also preserve existing metadata and binding checks.
